Query Lifecycle — from keystroke to response
1
User Input
frontend/script.js — sendMessage()
User types a query and presses Enter or Send.
Input is disabled, a loading spinner is shown, user message bubble is added to the chat.
POST /api/query { query: "...", session_id: "session_1" }
2
HTTP Endpoint
backend/app.py — query_documents()
FastAPI validates the request with Pydantic QueryRequest.
If no session_id, creates one via session_manager.create_session().
Delegates to rag_system.query().
3
RAG Orchestration
backend/rag_system.py — query()
Wraps query: "Answer this question about course materials: {query}"
Fetches prior conversation turns from SessionManager (up to MAX_HISTORY).
Calls ai_generator.generate_response() with the prompt, history, and tool definitions.
4a
Claude API — Call 1 (with tools)
backend/ai_generator.py — generate_response()
Sends system prompt + conversation history + user query to Claude.
tool_choice: auto — Claude decides whether to call search_course_content.

Path A: Claude answers directly → return text immediately.
Path B: stop_reason == "tool_use" → proceed to 4b.
4b
Vector Search (Tool Execution)
backend/search_tools.py → vector_store.py
ToolManager.execute_tool("search_course_content", query, course_name?, lesson_number?)

1. Resolve course name — semantic search on course_catalog ChromaDB collection.
2. Build filter — where: { course_title, lesson_number }.
3. Content search — vector similarity query on course_content collection using SentenceTransformer embeddings.
4. Format results with [Course - Lesson N] headers, store sources for UI.
returns formatted text chunks to Claude
4c
Claude API — Call 2 (synthesize)
backend/ai_generator.py — _handle_tool_execution()
Tool results are appended to the message thread as a tool_result block.
Second Claude call is made without tools — Claude synthesizes retrieved chunks into a final answer.
returns final answer string
5
Session Update
backend/rag_system.py + session_manager.py
Sources are collected from tool_manager.get_last_sources() then reset.
session_manager.add_exchange(session_id, query, response) saves the Q&A pair to history.
History is capped at MAX_HISTORY * 2 messages.
6
Render Response
frontend/script.js — addMessage()
Loading spinner removed. data.answer rendered as Markdown via marked.parse().
data.sources shown in a collapsible <details> block below the message.
Input re-enabled, focus returned to text box.
